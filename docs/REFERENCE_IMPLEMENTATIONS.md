# Reference Implementations

Evidence ledger for SynEEG firmware architecture and implementation decisions. Verified against the linked primary sources on 2026-07-14.

Public visibility is not permission to copy. A repository with no license is **reference-only** unless its copyright holder grants written permission. This ledger is an engineering record, not legal advice. License notices and third-party dependencies must be rechecked at the exact revision imported.

## Adoption boundary

- **Candidate code inputs:** GIBIC's ADS1299 driver and examples; Apache-2.0 portions of Synaps firmware; MIT portions of OpenBCI Cyton firmware; appropriately licensed STM32CubeG4 components; BrainFlow's MIT board-abstraction patterns, excluding separately restricted dependencies.
- **Architecture or behavioral references only:** Cyton-Mod, HANDS-EMG, Gen4, MicroEEG, IronBCI history, and the nRF52 implementation. They have no repository-wide license.
- **Copyleft isolation required:** FreeEEG32 and HackEEG must not be copied into a differently licensed SynEEG core without an explicit licensing decision and compliance plan.
- **Non-STM32 comparators:** OpenBCI Cyton, HackEEG, EEGFrontier, nRF52-ADS1299, the TI EVM, PiEEG, and BrainFlow are included because they establish useful acquisition, transport, validation, or host-integration patterns.

## Practical reuse order

1. Build the SynEEG-owned driver boundary and tests around the ADS1299 datasheet and TI EVM behavior.
2. Evaluate GIBIC as the only direct permissive ADS1299 driver import candidate; import by pinned commit with its MIT notice and a local review record.
3. Use Synaps and OpenBCI selectively for command, task, and compatibility behavior where their licenses and provenance are clear.
4. Use STM32CubeG4 only through a recorded component/license manifest.
5. Reimplement useful ideas from unlicensed repositories without copying expression, identifiers, tables, comments, or layout.
6. Keep copyleft implementations outside the firmware dependency graph unless SynEEG explicitly chooses their reciprocal terms.
7. Make BrainFlow compatibility a host-integration target, not an embedded architectural dependency.
